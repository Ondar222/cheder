# Сайт здравницы «Чедер»

Лендинг курорта на берегу озера Чедер (Next.js App Router, Tailwind v4, antd v6)
и кабинет менеджера для заявок и броней.

## Запуск

```bash
npm install
npm run dev        # http://localhost:3000
```

Скрипты: `dev`, `build`, `start`, `lint`.

## Переменные окружения

`.env` в репозиторий не кладётся (`.gitignore`), значения задаются на сервере.

| Переменная | Зачем |
| --- | --- |
| `VK_ACCESS_TOKEN`, `VK_OWNER_ID` | Посты группы vk.com/z_cheder в секции «Новости» |
| `NEXT_PUBLIC_YURTA_API` | API платформы Yurta для админки. По умолчанию `https://api.yurta.site` |
| `YURTA_API_BASE` | База API для серверного создания броней. Для теста — `https://test-api.yurta.site` |
| `YURTA_API_EMAIL`, `YURTA_API_PASSWORD` | Сервисный аккаунт отеля: под ним сервер создаёт бронь по заявке с сайта |
| `NEXT_PUBLIC_BOOKING_WEBHOOK` | Необязательно: дополнительный приёмник заявок (Telegram-бот, CRM) |

## Кабинет менеджера — `/admin`

- **Заявки** (`/admin`) — что отправили из формы «Забронировать»: контакты, даты,
  сумма, комментарий. Отсюда заявку можно перевести в бронь.
- **Брони** (`/admin/bookings`) — заезды санатория из Yurta за выбранный период и
  загрузка номерного фонда на сегодня. Список только для чтения: оплату,
  заселение и договор меняйте в партнёрском кабинете.
- **Создать бронь** (`/admin/new`) — комната из свободных на выбранные даты
  (занятые не дадут посадить двух гостей в один номер), гости, комментарий.

### Вход

Отдельной регистрации нет: вход под тем же логином и паролем, что в партнёрском
кабинете Yurta (`POST /auth/login/password`). Токены кладутся в `localStorage`
этого браузера — как в partners-next. Дополнительно сервер сайта выдаёт
httpOnly-cookie сессии: только по ней отдаётся список заявок с персональными
данными. Право смотреть брони санатория даёт роль аккаунта на стороне API.

### Как устроено

| Файл | Роль |
| --- | --- |
| `lib/session.ts` | Токены и пользователь в localStorage, снимок для `useSyncExternalStore` |
| `lib/api.ts` | Fetch к API Yurta: конверт `{ status, message, data }`, Bearer, повтор запроса после `/auth/refresh` на 401 |
| `lib/auth.ts` | `login()`, `logout()`, хук `useAdminAuth()` |
| `lib/bookingGrid.ts` | Общий контракт решётки: типы и нормализация ответа `/v4/booking/grid` для браузера и сервера |
| `lib/bookingApi.ts` | Клиентский слой админки: решётка, создание брони, сборка `additionalInfo` с паспортными данными |
| `lib/server/yurta.ts` | Серверный клиент API отеля: вход сервисным аккаунтом, кэш токена, решётка и создание брони |
| `lib/server/booking-from-lead.ts` | Подбор свободного номера под заявку и создание брони Yurta |
| `lib/leads.ts` | Заявки: серверный склад как основной, localStorage — резерв |
| `lib/datetime.ts` | Unix-секунды ↔ Dayjs, форматирование дат |
| `components/admin/*` | Оболочка с guard, форма входа, заявки, брони, создание брони |

### Как заявка становится бронью

1. Гость заполняет форму (`components/BookingModal.tsx`): ФИО каждого гостя, даты
   заселения и выезда, телефон, паспортные данные — и отправляет её.
2. `POST /api/leads` проверяет заявку, пересчитывает сумму и вызывает
   `lib/server/booking-from-lead.ts`.
3. Сервер под сервисным аккаунтом отеля (`YURTA_API_EMAIL` / `YURTA_API_PASSWORD`)
   берёт решётку на нужные даты, выбирает свободный номер под категорию и число
   гостей и создаёт бронь через `/v2/booking/room/prepaid`.
4. Заявка сохраняется с `bookingId` (или с `bookingError`, если бронь не встала —
   тогда менеджер оформляет её вручную из `/admin`).
5. Бронь видна в `/admin/bookings`: решётка отдаёт все заезды отеля, в том числе
   созданные в партнёрском кабинете и на другом сайте.

### Честное ограничение

В API Yurta сущности «заявка» нет — там сразу бронь, поэтому заявка с сайта
превращается в заезд при приёме: номер подбирается автоматически по категории и
числу гостей. Если свободного номера на даты нет или API недоступен, заявка всё
равно сохраняется — с причиной в поле `bookingError`, а менеджер доводит её до
брони вручную из `/admin` («В бронь»).

## Заявки с лендинга

`submitBooking()` (`lib/booking.ts`) отправляет заявку на сервер сайта
(`POST /api/leads`); он сохраняет её и создаёт бронь Yurta. Если приёмник
недоступен, `lib/leads.ts` кладёт заявку в localStorage браузера гостя. Гость в
любом случае видит подтверждение — форма не должна терять людей молча.
Дополнительно заявку можно дублировать во внешний приёмник через
`NEXT_PUBLIC_BOOKING_WEBHOOK`.
